# Rule reference

Generated by `skills/design-and-fix/scripts/gen_rule_docs.py` from the scanner rule registry. Do not edit by hand; run the generator after changing a rule.

Measured precision is the share of sampled signals a reviewer labelled true (`n` is the sample size; `unsure` labels are excluded) from `evals/precision.md`. Rules with no measurement show `unmeasured`.

Note: `no-version-prefix` fires on small unversioned services (internal or server-rendered apps that do not need versions); it is always low confidence.

Default `off` rules are dropped from the scan unless the config enables them with `"rules": {"<id>": {"enabled": true}}`; the scan lists them in `summary.default_off_rules` and `notes`.

Rails `resources` write routes whose scanned controller (with its scanned parents and included modules, followed 3 levels through app/controllers, app/helpers, app/models/concerns and lib) defines no such action are not listed; a controller with no methods, metaprogramming (method_missing, define_method, inherit_resources, alias), an unscanned parent, an include that is not scanned or an include line naming several modules keeps them (Rails framework modules define none). Security configuration applies only within the route's own app (the folder with its pom.xml, build.gradle, *.csproj, composer.json or Gemfile) or service; a Spring filter chain found only in another module makes the route unresolved. ASP.NET Core, Rails and Laravel actions named register/login/signup/password-reset are public by design (never under an admin path, controller or namespace), and (Spring, ASP.NET Core, Laravel) so is a POST to /users (/accounts, /members; never under an admin segment) beside an unauthenticated /users/login in the same file when its handler is registration-like: such an action name, an Auth/Account/Registration controller, or the controller serving that login itself (never an Admin-named controller).
